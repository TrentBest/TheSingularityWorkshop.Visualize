## Purpose

Coordinate the Renderer → Visualize contract and executable proof without merging overlapping work blindly or making either repository depend on the other in the wrong direction.

- **Renderer owns:** observer-relative representation/detail decisions, horizon/bucket scheduling, invalidation/reuse policy, and the resulting frame/trace semantics.
- **Visualize owns:** portable presentation/resource contracts, resource resolution and backend execution, frame submission, and backend diagnostics.
- **The adapter owns:** translating Renderer frame data into Visualize contracts while preserving ordering, stable entity identity, representation, transforms, and ranges. It does not imply resource ownership, upload completion, GPU execution, or device lifetime.
- **Host owns:** window/surface lifecycle and dispatching; it must not move those responsibilities into Renderer.

## Proposed acceptance criteria

- Renderer remains independently buildable and does not reference Visualize or GUI.SVG.
- Visualize integration tests exercise the actual Renderer public contract and preserve command order, entity IDs, representation, transforms, and index/instance ranges.
- The trace is schema-versioned and rejects unsupported versions or malformed records.
- Simulated completion is named in the schema/report and cannot be mistaken for production asynchronous completion.
- CI verifies generated artifacts and structured assertions; all documentation distinguishes CPU/SVG evidence from GPU/device evidence.
- No merge, release, or package publication is implied by this coordination document.
