# Singularity City massing proof

This sample builds one deterministic city geometry model, submits it through the public `Visualizer` API as a `VisualizerFrame`, and manifests that frame through the GUI.SVG backend. CI generates three SVG outputs from the same mesh and draw ordering:

- `singularity-city-noir.svg` — dark, high-contrast neon materials.
- `singularity-city-metro.svg` — warm neutral urban materials.
- `singularity-city-harmony.svg` — light, green-forward materials.

The skin is material and background configuration; it does not regenerate or reorder the city. The model includes a procedural street lattice, varied building heights, façade strips, and three landmarks. It is a rendering-path proof, not a statistically calibrated population model or a production GPU renderer.

## Run

From a Visualize checkout with the GUI repository available as the CI workflow expects:

```bash
dotnet run --project integrations/GuiSvg/CityMassingProof/CityMassingProof.csproj --configuration Release -- ./samples/CityMassing/generated
```

The output is generated by C# scene data → `VisualizerFrame` → `Visualizer.RenderAsync` → `GuiSvgVisualizerBackend` → GUI.SVG. The backend is CPU-side SVG manifestation; no GPU execution is implied.

The density statistics, occupancy allocation, street-network calibration, and connection to Renderer Event Horizon selection are deliberately separate next steps. This keeps the sample honest while establishing a real public-API path for the city scene.
