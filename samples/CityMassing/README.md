# Singularity City massing proof

This sample builds one deterministic city geometry model, submits it through the public `Visualizer` API as a `VisualizerFrame`, and manifests that frame through Visualize's direct `SvgVisualizerBackend`. CI generates three SVG outputs from the same mesh and draw ordering:

- `singularity-city-noir.svg` — dark, high-contrast neon materials.
- `singularity-city-metro.svg` — warm neutral urban materials.
- `singularity-city-harmony.svg` — light, green-forward materials.

The skin is material and background configuration; it does not regenerate or reorder the city. The model includes a procedural street lattice, varied building heights, façade strips, and three landmarks. It is a rendering-path proof, not a statistically calibrated population model or a production GPU renderer.

## Run

From a Visualize checkout:

```bash
dotnet run --project integrations/GuiSvg/CityMassingProof/CityMassingProof.csproj --configuration Release -- ./samples/CityMassing/generated
```

The output is generated by C# scene data → Renderer representation selection → `RendererFrameAdapter` → `VisualizerFrame` → `Visualizer.RenderAsync` → `SvgVisualizerBackend`. Each building receives a deterministic semantic entity ID, shared by all of its submitted face commands and preserved by the adapter into SVG `data-entity-id` metadata. The road network has its own stable entity ID. The backend is CPU-side static SVG manifestation; no GPU execution, depth buffer, general clipping, or interactive host is implied. GUI.SVG is not part of this scene-rendering path.

The fixture now includes a deterministic semantic hierarchy: districts contain parcels, and every building belongs to exactly one parcel and its parent district. District, parcel, and building identities are stable fixture IDs; the proof validates uniqueness and all parent references, writes district/parcel identity lists into the SVG root metadata, and records every building membership in the machine-readable report. These are domain-neutral proof records, not authoritative MyCity entities or imported parcel data. Population-density calibration and authoritative MyCity integration remain separate work.
